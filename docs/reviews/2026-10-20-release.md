# Release pipeline repair: 2026-10-20

The 1.0.3 candidate passed 430 functional tests, seven audit-policy tests, the
complete local gate, the six-job PR/main CI matrix, and the release verification
job. The protected publish job then failed with npm `EUSAGE` before uploading
the first package. Registry checks confirm that none of the 11 public 1.0.3
package versions was created.

The implicit pnpm publish command reproduced the same error in a nonpublishing
dry-run. Inspection also found that the publish job checked out fresh source and
installed dependencies without building, although compilation happened in a
different job. That could produce archives without `dist` if publishing proceeded.

## Repairs

- Use 1.0.4, keeping the failed v1.0.3 tag immutable as required by release policy.
- Build in the publish job, pack all public workspaces, and validate the actual
  archives before npm receives any publish request.
- Reject missing compiled entry points, declarations or CLI executables, wrong
  names/versions, private packages, and unresolved or mismatched workspace links.
- Publish explicit tarball paths through npm with provenance. Keep the protected
  environment, tag checks, full verification, and production audit policy.
- Add six archive regression cases and run real archive verification in all six
  CI jobs and the local release gate.

The approved dependency exception remains limited to the same advisory, package,
dependency path, pinned Mammoth version, and 2026-11-19 expiry. This release does
not expand or extend that risk acceptance.

## Verification commands

```sh
corepack pnpm verify
corepack pnpm audit:prod
corepack pnpm verify:publish-artifacts
```

The artifact checker also accepts a directory argument so the protected publish
job verifies the exact archives it will upload, rather than another temporary copy.

Local results: the full gate passed, including 430 functional tests, 13 script
tests, all 11 compiled tarballs, and the packed CLI installation smoke. The
production audit passed with the one previously approved exception. Publishing
an explicit core tarball with `npm publish --access public --provenance --dry-run`
also passed; this does not validate the CI-only OIDC credentials.
